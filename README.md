# 自習包廂｜座位狀態核對與模擬攝影機原型

> 教學研究原型，非北科大圖書館官方服務；沒有與實際攝影機、校務登入、館方門禁或座位系統串接。所有攝影機結果由原型管理員輸入，不會錄影或儲存影像。

## 問題與設計解法

**初步問題：**線上系統顯示空位，但座位現場可能已被物品占用；查找座位、重新登記、回報以及等候館員排除都不方便。報到、暫離與返回也可能缺乏即時狀態資訊。

**核心解法（模擬）：**假設有攝影機，電腦把「偵測到人／沒有偵測到人／背包／書籍」與座位在指定時段的登記狀態比對：

| 登記狀態 | 模擬攝影機訊號 | 系統行為 | 2.5D座位 |
|---|---|---|---|
| 有預約、尚未報到 | 偵測到人 | 記錄**模擬報到** | 紅色座位、出現小人 |
| 已報到 | 偵測不到人 | 標示**暫離**，座位仍保留 | 黃色座位、人物消失、有「暫」標記 |
| 暫離 | 再次偵測到人 | 標示**已回座** | 恢復紅色與小人，綠色提示 |
| 有預約、尚未報到 | 沒偵測到人 | 維持**待報到** | 紅色座位、無小人 |
| 無預約 | 偵測到人、背包或書籍 | 發出**待館員排除**的異常通報，暫停新登記 | 顯示人物／背包／書本與異常光圈 |
| 無預約 | 沒偵測到人 | 維持空位 | 可登記座位 |

一筆預約只有自己的到席狀態，不會因其他日期或時段的預約報到而誤改。館員確認現場已排除異常後按「確認排除・解除通報」，座位恢復依原型登記狀態顯示。學生也可點座位回報其他問題，並在「我的登記」追蹤處理進度。我的模擬登記保留已開始或結束的紀錄，但不再顯示「加入行事曆」及「取消預約」；時段判斷使用台北時間。

**報到入口現況：**目前只有原型管理員可在「管理測試」輸入模擬攝影機的人員偵測訊號，學生沒有自行點擊的線上報到按鈕。

**限制：**畫面「偵測到有人」無法判斷是不是當初預約的本人；此處的報到僅是**到席推估**，不是身分驗證。這個原型也不會因無人、暫離或長時間未報到而自動取消預約、判定違規或清除物品。真實應用前需處理誤判、遮擋、重複偵測、館方規則、隱私告知與人工覆核。

## 附加使用情境

三間**假設額外新建**的自習包廂，並不是主要解法：Cozy Room（12席閱讀角）、Sleepy Room（16席躺椅）、Discipline Room（20席共享長桌）。立體座位地圖用於呈現上述狀態與設備；配置、設備與席次均為概念設定，非校方正式資訊。

4. **[`supa/migrations/20261111_camera_checkin_demo.sql`](supa/migrations/20261111_camera_checkin_demo.sql)：本次新增的報到／暫離／回座模擬狀態及RPC，並支援未登記有人占位的異常。**

如果前三份都已成功執行，**只執行第四份即可**。不需要修改`supa/functions/account/index.ts`，也不需要Cloudflare或其他新服務。

## 功能測試

使用原型管理員（`profiles.role='librarian'`）進入「管理測試 → 模擬攝影機偵測」，選擇包廂、座號、日期與時段：

1. 在前端先登記該座位。管理端選「偵測到人」，模擬報到；3D出現小人，「我的登記」顯示已報到。
2. 再選「未偵測到人」，變成暫離；人物消失，座位仍是已預約。
3. 再選「偵測到人」，變成已回座。
4. 對沒有登記的座位選「偵測到人」或背包、書籍，會出現警報，館員清除後手動解除。
5. 在未報到前選「未偵測到人」，仍維持待報到，不會誤判暫離。

這個流程目前只測試管理員**輸入的模擬偵測結果**，不能聲稱已實現真實AI影像辨識或自動報到。
